## Catalog and language review

The candidate contains **17,628 English** and **17,970 Russian** string leaves. Relative to the previously published beta catalogs, English has 1,237 additions and 2 changed strings; Russian has 1,247 additions and 10 changed strings. Neither catalog removes keys. Russian-only `_few` and `_many` entries account for the 342-key count difference.

The new review baseline was the previously reviewed stable integration `364e448fa6bbd19c6012c42feaa55c306179be7c`, not an assertion that every inherited string was freshly retranslated. Against that baseline, 992 new Russian keys were checked against separate review packets. New routines, recovery notices, queued messages, connection setup, permissions, activity events and chat copy underwent Russian-only fluency review, independent English/Russian accuracy review, and final deterministic validation. Three existing composer strings and the updated Fast mode description received separate review. These were **agent reviews, not human translation certification**.

The other 255 additions and six older Russian changes are carry-forward values, verified identical both to that baseline and to the immutable stable catalog in `v2026.9.17.1`. They are not counted as fresh language reviews in this run.

Canonical agent prompts, raw diagnostics, protocol IDs, model/provider names, routes, user content and saved configuration remain unchanged. In particular, 23 routine instruction strings considered during inventory were excluded from the translated catalogs because they are agent instructions, not interface copy.

### Heuristic checks are not silently reported as green

- The skill's structural validator passed, including 497 plural groups. Generic strict parity reported the 342 intentional Russian CLDR expansion keys; missing keys and placeholder mismatches were both zero. The project's CLDR-aware validator passed.
- The Russian quality heuristic returned 363 candidates, not a raw pass: 229 matches for legitimate nouns such as «данные»/«данным», and 134 protected product or external-interface labels. These were triaged against the wording reviews; proper names and exact external controls were not mechanically translated.
- The generic length report contains 3,490 length warnings across the full inherited catalog (2,392 expansion and 1,098 long-string warnings), including 237 warnings on 214 newly reviewed keys. It is a review heuristic, not evidence of 3,490 broken layouts or exhaustive visual inspection. Browser validation sampled the changed screens, including wrapping security copy and external-help links; every screen and every warning were not visually certified.
- The incremental AST-based source inventory scanned 256 changed UI source files and produced 12 candidates, all triaged: product/protocol identifiers, translated-key references, URL/SSH examples and canonical fallback labels routed through display adapters. It does not trace every dynamic value or provider response.
- The broad source-plural heuristic has inherited false positives, including matches in identifiers/comments. No newly matching production UI lines were found in the reviewed delta; project CLDR and runtime tests remain the deterministic gates. A broad whole-repository hardcoded-text scan also includes generated build assets and is not used as a count of untranslated product messages.
- The README structure checker returned one link-target-difference finding: English/Russian pages intentionally point to their respective translated installation files and section anchors, and cross-link to one another. Those files and headings were checked; the new verification link is identical in both languages. This is an explained language-specific link mapping, not a raw checker pass.

## Remaining limitations and decisions

1. **Real deployed E2E was not run.** The owner's deployed instance is unreachable from the current local network. All browser work used isolated local fixtures with synthetic state, not the production server, database, credentials or provider accounts. OAuth/GitHub/Slack/MCP workflows were not exercised against live providers.
2. Full-monorepo tests/build, Storybook visual regression and exhaustive application-screen review were not run for this beta. A separate stable workspace typecheck encountered an unchanged native Cargo build requiring acceptance of the local Xcode/Apple SDK license; no system-license or dependency changes were made. That is not recorded as a beta typecheck attempt.
3. Unit-test output contains existing jsdom warnings for navigation, canvas and `scrollTo`. Production build reports large chunks and mixed import warnings. These are disclosed warnings, not failed tests or newly fixed upstream bundling behavior.
4. **Inherited English source-copy omission:** `sep28Apps.verifyPermissionsPending` instructs the user to set Contents/read and Checks/write, but omits Pull requests/write, which the server already requires. Russian preserves the current English instruction. Static inspection found that verification fails closed; it does not grant broader access. A separate source-copy correction should be reviewed before publication if the maintainer wants to resolve this upstream wording defect. No server permissions or policies were changed in this localization task.
5. Only English and Russian are supplied. Synthetic Arabic and other-language helper assertions test extensibility, not translation quality or complete RTL visual readiness. Raw third-party errors, agent output and user-authored material can remain in their original language.
6. The original upstream [PR #12989](https://github.com/paperclipai/paperclip/pull/12989) remains open and unmerged. Its source branch was not updated by the scheduled maintenance. Community updates do not imply upstream acceptance.

## Reproduce locally

Use a local Git clone containing the exact public upstream object and Node.js 24. These commands generate/test files locally; they do not publish or deploy:

```sh
npm run validate
PAPERCLIP_REVIEWED_SOURCE=/absolute/path/to/reviewed-integration npm test
npm run build -- --upstream /absolute/path/to/paperclip
npm run build -- --upstream /absolute/path/to/paperclip --check
npm run verify -- --upstream /absolute/path/to/paperclip
npm run check:release
node runtime/verify-three-locales.mjs --source /absolute/path/to/reviewed-integration
```

The optional source/runtime commands require a reconstructed reviewed integration with already-installed application dependencies, not a bare pristine upstream checkout. Use the generated installer only on the exact base in an isolated clean checkout; do not force it onto a different revision or downgrade a running application to match it.

Original localization attribution remains in [NOTICE.md](../NOTICE.md), including the [PR #11125](https://github.com/paperclipai/paperclip/pull/11125) lineage. Maintainer review, explicit release approval and deployment-specific validation remain necessary.
