The toolkit suite passed 107 tests; one optional community-runtime source-integration test is explicitly skipped in the standard invocation. That refusal protects against an unaudited runtime migration; the shipped stable uses `pinned-en-ru`. No hash guard was weakened. The initially missing current verification report was added before rerunning the standard suite. Exact-head GitHub CI is tracked on [PR #10](https://github.com/DrMaks22/paperclip-localizations/pull/10); publication requires it to pass.

An isolated Chromium production-build check verified dashboard EN/RU/EN switching, Russian dates/currency, raw names, document language, persisted preference after reload, the connector catalog, Slack purpose/agent steps and the first GitHub bot step. Slack's selected agent survived both language changes without saving. Desktop 1440×1000 and mobile 390×844 were inspected; no horizontal overflow on the mobile Slack step. Browser review found a real accessible-name issue: a translated action was concatenated with an uninflected app name. The follow-up uses a complete action/name template with a Russian separator and translates the fixed Connect/Add key helper labels, preserving raw names and action semantics. The final production build and type check passed; all 79 Browse tests and a fresh browser check passed. The full UI suite was not rerun after this four-file follow-up; its affected suite was.

Fixture-only response-shape errors were corrected without changing application source. Verified pages reported zero console errors and an expected service-worker-blocking warning. The final 345-request ledger contained no non-GET/HEAD requests. Cross-tab live locale synchronization failed an exploratory wait: the preserved stable runtime has no storage-event listener. Preference persistence on reload works. Closing the composer clears its draft, so that browser sequence is not claimed as an in-place draft-retention test; mounted component tests cover in-place language changes.

## Limits

UI checks use isolated synthetic data. Live OAuth/provider authorization, real file uploads, production server/database behavior and the user's Nano PC are outside this validation. Repository-wide backend suites were not run. New upstream commits require a new compatibility assessment; this patch intentionally refuses a different base. Merge and publication need separate owner approval.
