## What changed and why

Upstream PR #12989's desktop and mobile browser tests exposed a localization regression: FileCard's added aria-label changed the computed name from the visible `Download file` to `Download: <title>`. The official test deliberately locates the exact visible name inside the card identified by its filename heading. The same localization attribute was present in stable v2026.10.7.1.

This correction removes only that redundant attribute. The computed name is now the visible `Download file` / `Скачать файл`, matching the original English interface. Download URLs, filenames, content and actions are unchanged. Relative to the previous stable source, only three files change: the production attribute removal, two mounted URL/name regressions, and one related test expectation updated to the restored computed-name contract. No server, database, dependency, lockfile, deployment or protocol behavior changes.

The separate weekly-label defect reported in the master-only AI usage panel does not exist on this stable base. It is fixed and tested in beta, not copied into stable.

Greptile's later non-blocking suggestion to include filenames in every accessible link name is a reasonable separate accessibility enhancement. This package preserves upstream behavior; adopting a different name needs coordinated upstream browser expectations and assistive-technology validation. The recommendation remains visible in the upstream discussion, not silently marked resolved.

An isolated local fixture imported the actual FileCard, LocaleSwitcher and styles from the corrective source. RU → EN → RU updated both visible and computed link names while preserving the synthetic draft and raw artifact fields. Clicking the Russian link downloaded a synthetic local text file under the original filename; the downloaded bytes matched the fixture. No account, credentials or backend was used.

Desktop 1280 × 720 and narrow 390 × 844 dark-theme screenshots were inspected. The link remained usable, no overlap or horizontal overflow was observed, and document width equaled the narrow viewport. The final fresh browser tab had no console warnings/errors, blank screen or framework overlay. This verifies the changed source component, not all screens or authenticated backend flows. The final follow-up source commit changes only a test; the browser-tested production bytes are unchanged.

## Limitations and upgrade

- The optional skipped distribution test exercises a separate `community-json` fixture; this package uses `pinned-en-ru`. The stable installer is independently exercised by the exact round trip.
- Full-monorepo/native-runner compilation, Storybook and live-provider/backend E2E were not repeated locally. The previous full-workspace typecheck was blocked by this Mac's unaccepted Xcode SDK license; that host state was not changed. The upstream username-substring scanner's false positives remain documented in the [previous report](v2026.10.7.1.md).
- Existing Vite chunk/import warnings and nonfatal jsdom unsupported-browser-API notices remain. Passing checks do not prove an entirely defect-free application or universal translation of arbitrary dynamic content.
- User content, agent output, technical identifiers and unknown provider diagnostics remain in their source language. No new language review is claimed; the unchanged catalogs retain the previous Russian-only and bilingual agent-assisted review, not a claim of human editing.
- Exact-head GitHub package CI and published asset verification must be completed before claiming a published, checked release. Results belong to the maintenance PR and release record.
