# Paperclip Localizations — contributor and agent guide

This is an independent community localization distribution, not the Paperclip server or an official release. Preserve upstream attribution and the original localization authorship.

## Scope and safety

- English is the source catalog; Russian is the first reviewed translation. Never present copied English scaffolds as completed languages.
- Keep application behavior, protocol values, routes, user content, prompts, credentials, database state, and deployment configuration unchanged.
- The installer must be offline, opt-in, version-pinned, fail-closed, and reversible. Never use a forced patch, fuzzy merge, `git reset --hard`, a destructive checkout, or automatic dependency installation.
- Reject unsupported revisions and dirty or partially patched trees. Never restart or deploy a user's instance automatically.
- Generate release artifacts only from explicit reviewed Git object IDs, validated catalogs, and audited runtime overlays. A clean patch application is not proof of translation coverage or runtime correctness.
- Keep stable (official non-prerelease upstream tag) separate from beta (pinned master snapshot). Read `channels.json` and `docs/RELEASES.md`. Never promote master to stable by relabeling it. Beta must have a `-beta.N` tag, GitHub prerelease status and no `Latest` flag; published tags/assets stay immutable.
- Do not upload local paths, private logs, tokens, account data, or test fixtures from a real deployment.

## Collaboration

Use compact, self-contained subagent tasks without inheriting full conversation history. Separate implementation, native-language review, bilingual accuracy review, and installer safety review. Do not claim agent review is human review.

## Changes and verification

Use `apply_patch` for hand-written changes. Generated artifacts may be regenerated by reviewed repository scripts. Work only in assigned files when parallel agents are active.

Before publication, run repository tests, catalog validation, artifact reproducibility checks, and forward/reverse application checks against the locked upstream revision. For runtime changes, also run targeted application tests, typecheck, a production build, and browser checks on an isolated checkout. Report skipped or incomplete checks honestly.

Read `README.md`, `README.en.md`, `CONTRIBUTING.md`, and the maintenance and installation instructions in `docs/` when present. Never silently update compatibility claims or publish an unreviewed translation to satisfy a schedule.
