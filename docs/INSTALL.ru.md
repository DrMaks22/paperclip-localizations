# Установка

[Главная](../README.md) · [English](INSTALL.en.md) · [Установка с агентом](AGENT-INSTALL.md)

Патч применяется к исходникам конкретной ревизии Paperclip. Поддерживаемый коммит указан в `manifest.json` выбранного релиза. Для установщика нужны Node.js 24 и Git; требования к сборке уточняйте в документации этой ревизии Paperclip.

## Получить и проверить релиз

Клонируйте локализацию **за пределами** исходного репозитория Paperclip. В примере закреплён релиз `v2026.9.12.1`:

```bash
git clone --branch v2026.9.12.1 --depth 1 https://github.com/DrMaks22/paperclip-localizations.git
cd paperclip-localizations
node --version
shasum -a 256 -c SHA256SUMS
```

В Linux вместо `shasum -a 256` можно использовать `sha256sum`. Проверьте происхождение релиза, прочитайте `manifest.json`, `apply.mjs` и `paperclip-localizations.patch` перед запуском. Контрольные суммы помогают обнаружить повреждение файлов, но сами по себе не подтверждают, что автору можно доверять.

## Подготовить отдельный worktree

Замените абсолютные пути в командах на свои. Каталог `paperclip-localized` не должен существовать до выполнения команды. Исходный репозиторий должен содержать объект `baseCommit`; если Git его не находит, получите эту ревизию из доверенного upstream и повторите команду.

```bash
paperclip_base=$(node -p 'JSON.parse(require("node:fs").readFileSync("manifest.json", "utf8")).baseCommit')
git -C /absolute/path/to/paperclip worktree add --detach /absolute/path/to/paperclip-localized "$paperclip_base"
node apply.mjs --repo /absolute/path/to/paperclip-localized --check
node apply.mjs --repo /absolute/path/to/paperclip-localized --apply
```

Установщик требует точного совпадения коммита и чистого рабочего дерева. Если ревизия не поддерживается, есть локальные правки или патч применён частично, установщик остановится. Не обходите проверку принудительным применением, нечётким сопоставлением, сбросом изменений или понижением версии рабочего экземпляра.

Установщик работает без сети, не устанавливает зависимости, не обращается к базе данных и не запускает развёртывание. После применения установите зависимости, выполните тесты и проверку типов, затем соберите приложение для развёртывания по инструкции **закреплённой ревизии Paperclip**. Для этих этапов может потребоваться сеть. Просмотрите основные экраны с выбранным языком, используя тестовые данные. Развёртывайте сборку привычным способом только после проверки.

## Выбрать русский язык

В собранном приложении откройте меню профиля внизу боковой панели. В разделе **Language / Язык** выберите **Russian / Русский**. Выбор сохраняется в этом браузере; перезапуск сервера не нужен. При первом открытии приложение выбирает первый поддерживаемый язык из настроек браузера. Если ни один из них не поддерживается, используется английский. Переключитесь обратно на английский и перезагрузите страницу, чтобы проверить, сохранился ли выбор.

## Уже работающий Paperclip

Для действующего экземпляра сначала сохраните резервную копию базы данных и конфигурации штатным способом и подготовьте отдельную сборку. Храните резервные копии и секреты вне репозитория локализации. Учтите совместимость схемы базы данных: наличие патча для старого коммита не означает, что старую версию можно запускать с новой базой.

| Установка | Как использовать локализацию |
| --- | --- |
| Git-репозиторий | Создать отдельный worktree на поддерживаемом коммите, собрать и проверить. |
| Глобальный npm-пакет | Подготовить сборку из совместимых исходников; патч не устанавливается поверх глобального пакета. |
| Готовый Docker-образ | Собрать отдельный образ из совместимых исходников по принятой процедуре; патч не изменяет готовый образ. |

Если поддерживаемая ревизия не подходит для текущего экземпляра, дождитесь совместимого релиза локализации или подготовьте проверенное обновление патча. Не изменяйте `baseCommit` вручную, чтобы обойти проверку.

## Обновление и снятие патча

Применять патч повторно не нужно. Прямой `--check` проверяет готовность **чистых исходников** к установке и после применения завершится отказом. Проверить, что исходники точно соответствуют состоянию после применения патча, и затем снять его можно из каталога **того же релиза**:

```bash
node apply.mjs --repo /absolute/path/to/paperclip-localized --reverse --check
node apply.mjs --repo /absolute/path/to/paperclip-localized --reverse --apply
```

Снять патч не получится, если есть дополнительные правки или патч применён частично. Сохраните свою работу отдельно и изучите различия; принудительное применение не предусмотрено. Снятие меняет исходники, но не откатывает уже развёрнутую сборку или базу данных.

Для новой версии локализации предпочтителен **новый worktree** на её `manifest.baseCommit`. Проверьте новый релиз и повторите установку и сборку. Другой вариант — снять старый патч старым установщиком в прежнем checkout. Он должен точно соответствовать состоянию после применения старого патча. Затем перейдите к поддерживаемому коммиту с помощью привычных команд Git. Не накладывайте новый патч поверх старого.

## Если проверка не прошла

Сверьте `git rev-parse HEAD` с `manifest.baseCommit`, изучите `git status --short` в целевом worktree и повторно проверьте контрольные суммы релиза. Убедитесь, что используете правильное направление проверки. Для отчёта достаточно указать версию Node.js, релиз локализации, коммит Paperclip, выполненную команду и сообщение об ошибке без личных данных: [сообщить о проблеме](https://github.com/DrMaks22/paperclip-localizations/issues/new?template=installation.yml).
